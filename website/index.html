Everything in one workspace

Built for developers who live in terminals and compose files — with optional AI-assisted deploy suggestions and Tor/SOCKS support when you need it.

SSH servers

Add servers with host, username, and private key or password. Optional project path and working directory for commands. Test connection before you commit.

Remote file tree

Browse the server filesystem from the sidebar: open Dockerfiles, compose files, env files, and edit them in the editor area with familiar keyboard shortcuts.

Monaco editor

Same editor engine as VS Code for syntax highlighting and a comfortable editing experience on YAML, Dockerfiles, shell scripts, and more.

Docker overview

List containers from docker ps -a, inspect status, and jump into logs or terminal workflows for the selected server.

Compose logs

Tail Docker Compose logs in the bottom panel with optional service filter and line count. Stream logs over SSH when you need live output.

Deploy & presets

Run deploy commands such as git pull && docker compose up -d --build with one click. Save time with sensible presets for common flows.

Integrated terminal

Full xterm.js terminal over SSH: resize-aware, fit-to-panel, and ready for interactive sessions on the remote host.

Proxy & Tor

Optional global SOCKS proxy (e.g. Tor on 9050 or Tor Browser on 9150). Per-server toggle to connect directly when the host is clearnet-only.

Groq-powered assist

Optional Groq API key (stored locally) for AI-suggested deploy commands and helpers in the deploy flow — your key never leaves your machine except to Groq’s API.

Config generators

Scaffold nginx, Docker Compose snippets, and related config from structured forms — paste the output straight into your server tree.

Local workspace mode

Open a real folder from your own machine and use Server Operator against local files, local Docker, compose logs, databases, terminal workflows, and project shortcuts.

Voice input (optional)

Voice-to-text via Groq Whisper where supported — handy for long deploy notes or command dictation from the desktop app.

Project shortcuts for AI agents

Server Operator supports project-local command shortcuts in .server-operator/*.serop. Use the initializer to scaffold this folder, then let coding agents maintain these files in each repository.

Initialize a project

Creates deploy.serop, ops.serop, custom.serop, and AI context files so humans and agents follow the same structure.

$ curl -fsSL https://server-operator-zeta.vercel.app/init-server-operator.sh | sh
PS> iwr https://server-operator-zeta.vercel.app/init-server-operator.ps1 -UseBasicParsing | iex
$ npm run serop:init -- --path /path/to/project
$ serop .
$ npx server-operator-init --interactive --path .
$ npm i -D server-operator && npx server-operator-init --path .

What’s New in 2.10.0

The API Tester now imports Postman collections and environments, runs their scripts and tests, and can run a whole collection in order. A new Logs tab tails containers, services and log files in one colour-coded stream, and you can click an ID to follow a request across all of them.

v2.10.0

Chronicle

2026-10-23

API Tester

  • Import from Postman: paste a collection or environment JSON, or choose the files (several at once, or drop them on the list). Folders, inherited login and collection variables come across.
  • Variables: pick an environment next to Send and use {{name}} in the URL, params, headers, body and login. A line under the URL shows the final address and warns about any variable that has no value. {{$timestamp}}, {{$guid}} and {{$randomInt}} work too.
  • Postman scripts and tests run: pm.test, pm.expect, pm.response.json(), pm.environment.set and pm.collectionVariables.set. Results show in new Tests and Console tabs. Scripts run in a sandbox, so a collection cannot reach your servers or files.
  • Run a whole collection or folder with the play button. Requests go in order, variables such as a login token pass to the next one, and you see pass or fail, status and time for each, with a Stop button.
  • Make your own collections, add the open request to one, rename them, and export a collection or an environment as a Postman file. Deleting a collection, request or environment now asks first.
  • Copy as curl: one button copies the request as a curl command with the variables filled in.

Logs

  • New Logs tab. Tick containers, running services and log files such as nginx, or add any file path, and their lines stream into one view with a coloured label per source. It only reads: it never changes anything on the server.
  • Colour and highlighting: errors in red, warnings in amber, debug dimmed. HTTP status codes get badges (5xx red, 4xx amber, 2xx green), timestamps are dimmed and your search words are highlighted.
  • Search with an optional regex, hide noisy lines such as health checks, switch levels and sources on or off, pause, clear, and save what you see to a file.
  • Click any request ID, order ID, UUID or IP address to follow it across every source at once.
  • Stack traces fold under the line that started them, so one error is one row. Click the arrow to open it.

Frequently asked questions

Short answers about what Server Operator does and how it works. More detail is in the changelog and on GitHub.

What is Server Operator?

Server Operator is an open source desktop app for managing servers over SSH. It combines a remote file tree with the Monaco editor, Docker and Compose logs, deploy presets and an integrated terminal in one workspace.

Which operating systems does it run on?

Server Operator has builds for macOS (Apple Silicon and Intel), Windows (installer and portable) and Linux (.deb). Builds are published on the GitHub releases page.

How does it connect to a server?

You add a server with its host and username, then sign in with a private key or a password over SSH. A global SOCKS proxy such as Tor can be switched on, and each server can opt out of it.

Can I use it without a remote server?

Yes. Local workspace mode opens a folder on your own machine, with file browsing, terminal, Docker, compose logs, database tools, deploy commands and .serop shortcuts. No SSH is involved.

Where is my Groq API key stored?

The optional Groq API key is stored locally on your machine and is sent only to the Groq API, to power deploy suggestions and voice input. The app works without it.

What are .serop shortcut files?

They are project-local command shortcuts kept in .server-operator/*.serop. The initializer scaffolds deploy.serop, ops.serop and custom.serop so people and coding agents share one structure.

Is Server Operator free and open source?

It is open source under the Apache License 2.0, and the source and releases are on GitHub.

Mac says Serop is “damaged”?

The Mac app is not signed with an Apple certificate yet, so macOS can block it the first time you open it. The app is fine, and one command fixes it.

  1. Drag Serop into your Applications folder.
  2. Open Terminal, paste this and press Enter:
    $ xattr -cr /Applications/Serop.app
  3. Open Serop again.
