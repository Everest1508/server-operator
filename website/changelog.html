Changelog

Every release of Server Operator, from the initial launch to the latest update.

v2.12.1

Beacon

2026-10-28

Teams now has its own icon in the left bar and the page scrolls properly. Shared servers are gone, so you only see the projects you were given. Docker compose commands with -f now run in a project when the file is inside the project folder.

Teams

  • Teams has its own icon in the left bar, with a count of pending invitations, instead of hiding in the profile menu.
  • Shared servers are removed. Teams now shows your teams, invitations and the projects you can open.
  • The Teams page scrolls again and no longer shows the screen behind it.

Commands

  • docker compose commands with -f now run in a project, with or without sudo, as long as the compose file is inside the project folder. Files outside it, and -p, stay locked.
v2.12.0

Lantern

2026-10-28

Projects now have their own icon in the left bar. Open a project and you get its Docker containers, its files and its saved commands, kept inside the project folder, with only safe commands allowed to run.

Projects

  • A Projects icon in the left bar lists your projects and shared servers with their folders. Click one to open it.
  • Opened projects get a Files view that stays inside the project folder. Paths outside it are refused.
  • The Docker side list shows the project name and folder and only that project's containers. Server addresses are no longer shown for projects.

Commands

  • A new Commands view runs the shortcuts in the project's .server-operator folder and streams their output, with a Stop button.
  • Only safe commands run in a project: looking at files and logs, git pull, and docker compose up, down and restart, with sudo allowed before git and docker. Everything else shows as Locked with the reason.

Fixes

  • Docker services now load for a project, so the project's compose services are no longer empty.
  • Sign-in and team loading no longer fail with Failed to fetch against the hosted CRM.
v2.11.1

Relay

2026-10-23

Serop can now update itself. When a new version is out you get a box with Update now or Later, and Update now downloads and installs it, so there is no more going to GitHub to download. Mac downloads are now signed and notarized by Apple, so macOS no longer says the app is damaged.

Updates

  • Update from inside the app: when a new version is out, a box asks Update now or Later. Update now downloads it with a progress bar and restarts Serop in the new version. It works from 2.11.1 onward; older versions need one last manual download.
  • Choose Later and a small "Update available" button stays in the top corner. Click it whenever you are ready.
  • The update box shows what changed. Release notes now list the real changes, not just a commit number.

Mac

  • Mac downloads are signed and notarized by Apple, so macOS opens Serop with a double-click and no "app is damaged" warning.
v2.10.0

Chronicle

2026-10-23

The API Tester now imports Postman collections and environments, runs their scripts and tests, and can run a whole collection in order. A new Logs tab tails containers, services and log files in one colour-coded stream, and you can click an ID to follow a request across all of them.

API Tester

  • Import from Postman: paste a collection or environment JSON, or choose the files (several at once, or drop them on the list). Folders, inherited login and collection variables come across.
  • Variables: pick an environment next to Send and use {{name}} in the URL, params, headers, body and login. A line under the URL shows the final address and warns about any variable that has no value. {{$timestamp}}, {{$guid}} and {{$randomInt}} work too.
  • Postman scripts and tests run: pm.test, pm.expect, pm.response.json(), pm.environment.set and pm.collectionVariables.set. Results show in new Tests and Console tabs. Scripts run in a sandbox, so a collection cannot reach your servers or files.
  • Run a whole collection or folder with the play button. Requests go in order, variables such as a login token pass to the next one, and you see pass or fail, status and time for each, with a Stop button.
  • Make your own collections, add the open request to one, rename them, and export a collection or an environment as a Postman file. Deleting a collection, request or environment now asks first.
  • Copy as curl: one button copies the request as a curl command with the variables filled in.

Logs

  • New Logs tab. Tick containers, running services and log files such as nginx, or add any file path, and their lines stream into one view with a coloured label per source. It only reads: it never changes anything on the server.
  • Colour and highlighting: errors in red, warnings in amber, debug dimmed. HTTP status codes get badges (5xx red, 4xx amber, 2xx green), timestamps are dimmed and your search words are highlighted.
  • Search with an optional regex, hide noisy lines such as health checks, switch levels and sources on or off, pause, clear, and save what you see to a file.
  • Click any request ID, order ID, UUID or IP address to follow it across every source at once.
  • Stack traces fold under the line that started them, so one error is one row. Click the arrow to open it.
v2.9.0

Courier

2026-10-19

A new API Tester tab works like Postman: send a request to any URL, public or on your own computer, and read the response. Paste a curl command to fill it in, and let Serop find the web apps running on your server.

API Tester

  • New API Tester tab. Pick GET, POST, PUT, PATCH, DELETE and more, type a URL (public, or localhost for an app on your computer) and see the status, time, size and a formatted response.
  • Paste a curl command into the URL box and Serop fills in the method, URL, headers, body and login for you. Chrome's Copy as cURL works too.
  • Add query params, headers, a JSON or text body, and a token or username and password. Save requests to the list on the left to run them again.
  • Find APIs on your server: one button lists the web apps running on the connected server, named by Docker container or program and marked Public or Private. Click one to fill in its URL. Databases, mail and SSH ports are skipped.
  • Errors are in plain words, such as nothing listening on that port or host not found. For a self-signed HTTPS certificate you can choose Allow untrusted certificate.
v2.8.0

Countdown

2026-10-15

Scheduled commands now show a live toast: a countdown to the start, then the job's output as it runs, then the result with its exit code. You can cancel a schedule before it starts or stop a running job. Multi-line shortcuts now schedule correctly, and the date and time picker is easier to use.

Scheduled commands

  • Shortcuts with several lines, or with quotes or a % sign, broke the schedule, and Serop still said Scheduled. They now schedule correctly, and an install that fails shows its error.
  • A toast counts down to the start of a scheduled command, then shows its output as it runs (refreshed every 2 seconds) and ends with finished or failed and the exit code.
  • Stop a running scheduled command from the toast or the sidebar, or cancel a schedule from the toast before it starts.
  • Started, finished and failed notifications arrive as a toast, a bell entry and a system notification, from whichever screen you are on. If a job is still waiting in cron two minutes after its time, you are told to check that cron is running.
  • Cron fires on the server's clock, so on a server in another timezone a job ran hours late. The server now converts the time you picked, and times show in 12-hour form.
  • The date and time picker has a solid background and typed hour and minute boxes with an AM/PM switch, so any minute can be chosen.
v2.7.2

Clockwork

2026-10-15

Scheduled commands now fire at the time you picked even when the server is in another timezone, and Serop shows the real error when the job could not be installed.

Scheduled commands

  • Cron runs on the server's clock, so on a server in UTC a time picked in your timezone fired hours late. The server now converts the exact moment you picked into its own time. Cancel and schedule existing jobs again to get the fix.
  • A failed crontab install still showed Scheduled. It now shows the error, for example when crontab is missing on the server.
v2.7.1

Right on Time

2026-10-15

Scheduled commands now really run: they start in your project folder with a full PATH, and the date and time picker matches the app theme. A single deploy shortcut runs in the deploy terminal.

Scheduled commands

  • Scheduled commands ran from the home folder with a bare PATH, so project commands such as docker compose or ./deploy.sh failed without any message. They now start in your project folder with the usual tool folders on PATH, and a % in a command no longer cuts it short. Schedule existing jobs again to get the fix.
  • A built-in date and time picker replaces the white browser one, with a calendar, hour and minute buttons and AM/PM, in the app theme.

Deploy

v2.7.0

Full Spectrum

2026-10-14

Terminals come in full colour and gain search, clickable links and split view. Jump to any file with Cmd/Ctrl+P, drag files onto the file tree to upload them, and preview images and PDFs. A new Git tab shows what is on the server, the database editor keeps your query history, and a notification centre keeps deploy results.

Terminal

  • Terminals on servers had no colours, because Serop opened them as a plain vt100 terminal. They now open as a full 256-colour terminal, with a colour palette that follows your theme.
  • When the server's prompt has no colours of its own, the session gets a coloured prompt and coloured ls and grep. Custom prompts such as Ubuntu's, oh-my-zsh or starship are left alone, and nothing on the server is changed.
  • Resizing the terminal panel never reached the server, so long lines and full-screen tools wrapped at 80 columns. The server now always knows the real size.
  • Search the terminal with Cmd/Ctrl+F, with a match count, next and previous, and a match-case toggle.
  • Links in terminal output open in your browser. Icons from tools like eza and lsd show when a Nerd Font is installed.
  • Split view shows two terminals side by side. Rename a terminal tab by double-clicking it or pressing F2.

Files

  • Go to any file on the server with Cmd/Ctrl+P (File, Go to File). It matches as you type, skips folders like node_modules, and lists recent files.
  • Drag files from Finder or Explorer onto the file tree to upload them into that folder. On a production server you confirm with its name first.
  • Images and PDFs open as a preview. A path bar above the editor shows where the file is, reveals its folders in the tree and copies the full path.
  • Binary files opened as base64 text, and saving them would have overwritten the real file. They now show a preview or a download button and cannot be saved as text.

Git

  • A Git tab in Deploy shows the server's branch, how far it is ahead of or behind upstream, uncommitted changes with their diffs, and recent commits with their patches.
  • Fetch, pull (fast-forward only), stash all changes, or discard the changes to one file. Risky actions ask first, and production servers ask for their name.

Database

  • Select part of the SQL to run only that part, and run with Cmd/Ctrl+Enter.
  • Every query you run is kept in History for that server and database, with row counts, timings and failures. Save queries you use often by name.

Notifications

  • A bell in the title bar keeps finished, failed and cancelled deploys and connection problems, even after a restart. Click a deploy to open its output again.
v2.6.0

Red Ink

2026-10-13

Mark your production servers so they show in red and ask you to type their name before anything risky runs. Deploys now really run in the background, with a live panel that follows them on every screen and a system notification when they finish. The editor keeps each file's undo history, highlights server files and gains a status bar, and copy and paste work on Mac again. The server sidebar is reworked too.

Production mode

  • Mark any server as production from its settings, or with the shield button on its row in the sidebar. You turn it on and off yourself, and turning it off asks you to type the server name.
  • On a production server, risky actions ask you to type its name before they run: deploy, rollback, Docker kill and remove, firewall changes, database wipe and import, deleting rows and files, stopping nginx, and removing the server.
  • Production servers are marked in red: a line under the title bar with a Production badge, red server tabs, and red cards on the Servers page and in the deploy panel.

Live deploys

  • Deploys started from a .serop shortcut still stopped when you switched servers, because the background part of 2.5.1 was not finished. They now run in the background and keep going whatever screen or server you are on.
  • A deploy panel in the bottom-right corner shows every running deploy with its server, a timer and live output, on every screen. Expand it to read the last 300 lines, or cancel a shortcut deploy.
  • The Git deploy shows in the panel too, so its output is no longer lost when the terminal closes.
  • When a deploy ends while Serop is in the background, you get a system notification. Click it to open that deploy's output.
  • A long deploy no longer loses its SSH connection to the 5-minute idle timeout.

Editor

  • Switching tabs reset the editor, so undo history, the cursor and the scroll position were lost. Each file now keeps them, and undo still works after you leave the Files view and come back.
  • Highlighting for the files you edit on servers: nginx configs (including sites-available files with no extension), .env files, systemd units, INI and TOML, Dockerfiles, shell dotfiles and many more languages.
  • Log files are highlighted too: timestamps, errors, warnings and IP addresses each get their own colour.
  • The editor uses your Serop theme's colours, including custom themes, instead of a fixed dark or light theme.
  • A status bar under the editor shows the line and column, indentation, line endings and language, with word wrap and minimap toggles. Change any of them from there.
  • Shell scripts, .env files and similar files with Windows (CRLF) line endings get a warning, because they can break on a Linux server, and a one-click Convert to LF.
  • On macOS, paste did not work anywhere, and copy, cut, undo and select all were unreliable in the editor and the terminal. They now work in the editor, the terminal and text fields, from the keyboard and from the Edit menu.

Server sidebar

  • Production servers are grouped at the top. Each server shows its connection type, whether it is open in a tab, and a Deploying indicator while a deploy runs on it.
  • A search box appears once you have more than five servers, and the row buttons can be reached with the keyboard.
  • Removing a server from the sidebar deleted it straight away. It now asks first.

v2.5.0

Fresh Coat

2026-10-09

A clean-up of how Serop looks and reads, plus fixes for Docker and Logs on local folder projects. You can now choose which Groq model powers the AI helpers, and the riskiest database buttons ask before they run.

Docker and Logs

  • The Actions menu on containers and services opened but stayed invisible. It now appears where you click, and so do the other drop-down menus that share it.
  • A folder you add as a project now shows up in Docker and Logs. Serop checks the folder for a compose file and adds it for you. The Logs panel also has a Use project folder button.
  • Containers and services are rows with Start, Stop, Restart and Logs on the row itself. Pause, Kill, Remove and the shell and database clients are in the more-actions menu.
  • Kill, Remove and Restart all now ask you to confirm. Log views have a filter box and a Copy button, and the Logs panel can clear a tab.
  • The Docker sidebar lists the containers on your server with a running, paused or stopped dot. Docker and Deploy no longer repeat your server list once you are connected.

Look and feel

  • The app uses a clean system font for menus and labels. Code, paths, logs and the terminal stay monospace. Keyboard focus is clearly visible, scrollbars are softer, and animations calm down if your system asks for reduced motion.
  • Title bar menus open on hover once one is open, close with Escape, and show the right shortcuts for your system. Menus and drawers are solid instead of see-through. The About box shows the real version.
  • Server tabs show the connection type. The sidebar shows each server host or folder, and a green dot for the one you are connected to. The Overview page shows memory and disk as cards and explains why local projects have no stats.
  • Small all-caps labels, tiny text and pulsing badges were replaced across the app with readable, sentence-case wording. Empty states now say what to do next.
  • Settings lists the always-on core modules as a quiet list instead of eight greyed-out switches. Section titles are plain text, long theme names wrap instead of being cut off, and a custom theme's Edit and Remove buttons can be reached with the keyboard.
  • Confirmations and notices are now Serop dialogs instead of the plain system pop-ups. They match your theme, put the safe choice (Cancel) in focus for risky actions, close with Escape, and name the action on the button, like Delete or Turn off.
  • The Files sidebar has a new look when you are not connected: a terminal that cannot find your files, and a joke.

Files and editor

  • Press Cmd or Ctrl + S to save the open file.
  • Tabs show a dot when a file has unsaved changes. The file open in the editor is highlighted in the file tree. The toolbar no longer repeats the File menu, and the minimap is off.

Deploy

  • Deploy and Rollback now ask you to confirm. Deploy resets the server folder to the remote branch, and Rollback checks out an older commit. Stopping, disabling or restarting nginx in Server admin asks too.
  • Tabs are Terminal, Git deploy, Config creators and Server admin. The Git deploy form uses plain wording, the Deploy button matches the rest of the app, and Deploy history shows Succeeded or Failed with a Show output button.
  • The AI chat asks for your Groq key once and then shows Groq key saved with a Change link. Its empty state offers example prompts you can click. The suggested command button now says Run in terminal.

Firewall

  • Turning the firewall on without an Allow rule for SSH could lock you out of the server. Serop now warns first. Deleting the SSH rule, blocking port 22, or turning the firewall off also asks you to confirm, and presets list the rules they will add.
  • Deleting a firewall rule uses its number in UFW. Serop now checks that the number still points at the rule you clicked before deleting, and asks you to refresh if the list changed.
  • Ports, source addresses and subnets are checked before they are used in a command on the server. The tabs are Open ports, Firewall rules, Presets and Port scanner, with plain wording and no all-caps labels.

AI helpers

  • Choose the Groq model for Deploy chat and Config Creators from a drop-down next to your API key. Serop remembers your choice and loads the models available to your key. Deploy chat still falls back to other models if you hit a rate limit.

Database safety

  • Import Full SQL deletes everything in the database before importing, with no warning. It is now called Wipe and import, and asks you to confirm. Restoring a Cloudinary backup also asks first.
  • Connection buttons and messages use plain words, such as Connect, Disconnect and Connected via local port. Input fields show a focus outline for keyboard users.

v2.3.0

Iron Palette

2026-10-04

Tightens security and adds custom themes. Serop now checks SSH server fingerprints, encrypts saved passwords with your system keychain, and keeps secrets out of its log file. Themes can be loaded from JSON files, including files shipped by an installer.

Security

  • SSH host key check. The first time you connect to a server, Serop shows its fingerprint and asks you to trust it. Later connections are silent if it matches.
  • If a server fingerprint changes, Serop stops and shows the old and new fingerprints before you decide. Fingerprints are saved in known_hosts.json in the app data folder.
  • Saved server passwords and the Cloudinary secret are encrypted with the system keychain (Keychain, Credential Manager, or the Linux keyring). Passwords saved by older versions are encrypted the next time the app saves.
  • Passwords stay plain text only on Linux systems with no keyring, because Electron has no real protection there.
  • The log file no longer records passwords, tokens or keys. Password-like text is scrubbed, long command output and SQL are cut to 200 characters, and failed SQL imports no longer log the statement. Old log entries stay until you clear the log.

Custom Themes

  • Import a theme from a JSON file in Settings (name, light or dark base, and colors). Any color you leave out comes from the base theme. A Template button downloads an example file.
  • Themes can also come from folders: the installer themes folder, the folder in the SEROP_THEMES_DIR environment variable, and a themes folder in the app data folder. Settings has Themes folder and Reload buttons.
  • Theme files are checked before use. Invalid colors, values like url(...), files over 20 KB, and more than 20 imported themes are refused with a clear message.
  • The terminal and editor follow custom theme colors.

Housekeeping

  • Removed a stray vite config timestamp file that was committed by mistake and ignored it in git.

v1.0.1

Amber Anchor

2026-06-02

This release introduces critical SSH stability improvements, a connection queuing manager to prevent session exhaustion, custom toggles, password visibility eye toggles, multi-architecture macOS build support, Tailwind CSS v4 styling migration, and significant CPU optimization by removing redundant periodic uptime monitoring loops.

SSH Stability & Queuing

  • Implemented a sequential FIFO Promise queue (connectionQueues) to serialize remote execution requests and prevent MaxSessions channel open failures.
  • Added SSH keepalive heartbeats (keepaliveInterval: 10000, keepaliveCountMax: 3) to automatically teardown dead or timed-out connection sockets.
  • Cleared connection queue state upon socket closure, errors, or idle timeout evictions to prevent reference memory leaks.
  • Completely removed the 60-second periodic background uptime monitoring checks to eliminate unnecessary SSH load on servers.

Visual Refinements & Controls

  • Integrated an interactive eye icon visibility toggle for masked server passwords under the Authentication table column.
  • Replaced native browser checkboxes across server configuration forms, Docker views, and settings with sleek custom React buttons.
  • Fixed bottom terminal active checks to prevent active SSH stream sessions from unmounting and disconnecting during drawer toggles.
  • Migrated custom UI styling and theme colors to Tailwind CSS v4 design specifications.

Deployment & Core Infrastructure

  • Configured explicit multi-arch macOS targets supporting both Apple Silicon (ARM64) and Intel (x64) architectures.
  • Refined Certbot automatic SSL detection and status verification logic for server domains.
  • Optimized Tor SOCKS5 proxy toggle defaults for SSH connections.
v1.0.0

Cobalt Catalyst

2026-05-27

The first full release of Serop — a desktop server management suite built on Electron, React, and SSH. Cobalt Catalyst introduces an auto-updating notification system, a custom app logo icon, and a default-disabled feature toggling mechanism.

Auto-Update System

  • GitHub Releases API silent check to automatically check for new versions on launch
  • Non-intrusive floating toast alerts for new release tags with an expandable changelog body
  • Persistent version dismissals stored in local storage to prevent duplicate alerts
  • Check for Updates option inside the application Help menu

Visual Identity & Custom Icon

  • New custom-designed squircle brand logo mark deployed at all standard system icon sizes
  • Support for dynamic Dock icon loading at runtime during macOS development

Disabled-by-Default Feature Suite

  • All optional server and deployment modules disabled by default on clean installations
  • On-demand opt-in control panel allowing users to only turn on features they require

SQL Query Runner

  • Monaco Editor input with SQL syntax highlighting for MySQL and PostgreSQL
  • Run button that executes queries over the SSH-tunneled database connection
  • Paginated results table with row count and execution time display
  • Inline error reporting for database and connection failures
  • Autocomplete for table names pulled from the live schema

Git Deployment Pipeline

  • Server + project directory selector with one-click Deploy action
  • SSHes in and runs git pull, npm install / pip install, migrations, and service restart
  • Supports pm2 restart and systemctl restart as service managers
  • Real-time output streamed into the integrated terminal during deployment
  • Terminal input is locked while a deployment is in progress

Deployment History & Rollbacks

  • All deploys logged to a local SQLite table (timestamp, branch, commit hash, status, output)
  • Per-server/project deploy history list with colored success/failure badges
  • Visual log viewer with expandable terminal output per deploy entry
  • Rollback button — SSHes in, runs git checkout <commit>, and restarts the service

Terminal Snippet Library

  • Save commands with a title, description, and body to a persistent local library
  • Searchable side panel with instant fuzzy filtering across all snippets
  • Click a snippet to paste it directly into the active terminal
  • Variable placeholder support: {{domain}}, {{port}}, etc. — prompts for values before pasting
  • Copy-to-clipboard button on every snippet card
  • Seed snippets included out of the box (nginx reload, pm2 status, docker prune, etc.)

Core Infrastructure

  • Electron + React + TypeScript foundation with Vite bundler
  • SSH connection manager with EC2 key-pair, password, and Cloudflare Tunnel modes
  • Tor SOCKS5 proxy support for anonymous SSH connections
